# Submission Snapshot Procedure

Award-winning hackathon repositories often preserve the exact submission state so later cleanup does not blur what judges originally saw. Before the deadline:

1. Ensure all final links in `SUBMISSION.md` work.
2. Update `IMPLEMENTATION_STATUS.md` honestly.
3. Run the evaluation set and record results.
4. Capture final real screenshots.
5. Commit final submission materials.
6. Create a tag such as `hackathon-submission-v1`.
7. Optionally create an immutable branch such as `archive/hackathon-submission-v1`.
8. Continue post-hackathon improvements on `main` only after the snapshot exists.

Do not alter the archived submission to make later features appear as if they existed at judging time.
